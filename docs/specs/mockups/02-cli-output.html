ja4plus command-line output

The four states the README documents. Values are real fingerprint shapes, not placeholders.

Read a capture

The default output prints one line per fingerprint, in capture order.

$ ja4plus testdata/foxio/pcap/tls12.pcap

4   ja4     192.168.133.129      34.117.237.239:443       t13d1715h2_5b57614c22b0_3d5424432f57

Read a capture as JSON

The --json flag emits one object per fingerprint, including the raw forms.

$ ja4plus --json testdata/foxio/pcap/tls12.pcap | jq -c '.[3]'

{"type":"ja4","fingerprint":"t13d1715h2_5b57614c22b0_3d5424432f57",
 "raw":"t13d1715h2_002f,0035,009c,009d,1301,1302,1303,c009,...",
 "raw_original_order":"t13d1715h2_1301,1303,1302,c02b,c02f,cca9,...",
 "src_ip":"192.168.133.129","src_port":36372,
 "dst_ip":"34.117.237.239","dst_port":443,
 "timestamp":"2024-03-11T14:22:07.118431Z"}

Inspect the database

Two states: the embedded copy, and a downloaded cache.

$ ja4plus db info

source     embedded
records    108
path       (none — using the copy compiled into the binary)

Run `ja4plus db update` to download the current database.

$ ja4plus db update
downloading… 4.6 KB  validating… 112 records  writing cache
updated: 108 → 112 records

$ ja4plus db info

source     cache
records    112
path       ~/.cache/ja4plus/ja4plus-mapping.csv
updated    2026-08-06 14:31:02 UTC

Failures

Every failure names the cause and exits with a non-zero status.

$ ja4plus missing.pcap
error: cannot open missing.pcap: no such file or directory
exit status 1

$ ja4plus corrupt.pcap
error: corrupt.pcap is not a pcap or pcapng file
exit status 1

$ ja4plus db update
error: cannot reach https://ja4db.com/api/read/: timeout after 10s
the existing database is unchanged
exit status 1

$ ja4plus --version
ja4plus v1.0.0
Mockups convey intent, not a contract. The implementer may change the column layout, the flag names or the exact wording, as long as the requirements and the acceptance criteria in features/09-database-lookup.md and features/10-release.md are met. The rule these screens do fix is that every failure names its cause and exits non-zero, and that the library itself writes nothing — all output belongs to the command-line program.
