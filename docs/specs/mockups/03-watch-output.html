The statistics line

FR-capture-28 through FR-capture-34. Every field, and where it comes from.

FieldMeaningSource
uptimeWhole seconds since the monitor started.The monitor.
packetsPackets the monitor read.The monitor loop.
fingerprintsResults the processor returned.The processor.
droppedPackets the capture backend dropped. Reads unknown when the backend reports none.The packet socket, on Linux.
connectionsEntries the connection table holds.The monitor.

The two failures an operator meets first

No permission. FR-capture-35 and FR-capture-36.

standard error
$ ja4plus watch --interface eth0
ja4plus: cannot open eth0: operation not permitted
The monitor needs CAP_NET_RAW on this host.
Run the command with sudo, or grant the
capability to the program:
  sudo setcap cap_net_raw+ep $(which ja4plus)
$ echo $?
2

macOS without the build tag. FR-capture-24.

standard error
$ ja4plus watch --interface en0
ja4plus: the monitor is unavailable in this build
The pure-Go capture backend supports Linux
only. On macOS the monitor needs libpcap,
which is an opt-in build:
  go build -tags libpcap ./cmd/ja4plus
Reading a capture file needs no build tag.
$ echo $?
1

Both messages name the repair rather than the fault alone. The second one also states what still works, because a user who cannot run watch can still run ja4plus capture.pcap.
