Executive summary

ja4plus-go is a Go library and command-line program for JA4+ network fingerprinting. It implements ten JA4+ methods and is at version v0.3.0. This spec takes it to v1.0.0, which is an API freeze.

A freeze is only safe when three things are true, and none of the three is true today.

The three blockers

  • Conformance is untested. The library claims to implement the FoxIO specification. One expected-output file covers two methods on one capture. FoxIO publishes 38 captures and two vector sets, and nothing in this repository reads them.
  • The concurrency contract does not exist. Nine of the ten fingerprinters hold unguarded maps and slices. JA4XFingerprinter alone holds a mutex. GetShardKey implies a shard-per-goroutine design that no exported document states, so a caller who shares one Processor writes a data race and gets no warning.
  • The license is wrong. The README claims BSD 3-Clause and links to a LICENSE file that does not exist. FoxIO licenses nine of the ten methods under FoxIO License 1.1, which permits non-commercial use only.

This spec closes all three, adds the gates that keep them closed — conformance, fuzzing, race detection, vulnerability scanning and a coverage floor — and then releases v1.0.0. The full text is in spec.md.

Goals and non-goals

Goals

  1. Every method produces the exact fingerprint the FoxIO reference produces, for every capture in the corpus.
  2. The concurrency contract is documented on every exported type, and a race test proves it.
  3. The license files state the FoxIO terms for the nine FoxIO-licensed methods.
  4. CI gates conformance, race detection, fuzz testing, vulnerability scanning, lint and coverage on every pull request.
  5. The library releases as v1.0.0 with a frozen exported API.
  6. The README, the package documentation and the CHANGELOG describe the released behaviour and nothing else.

Non-goals

  • No eleventh method. JA4E, JA4LS, JA4SScan and JA4TScan stay out of scope.
  • No live network capture. The caller supplies packets.
  • The library does not become a network monitor.
  • No change to the Python port. A parity gap found here becomes an issue in Crank-Git/ja4plus, not code here.
  • No commercial license is sought from FoxIO as part of this work.

Key choices and why each beat the alternative

ChoiceAlternativeWhy it wins
Go 1.24 module floorGo 1.22 or 1.23 Go 1.22 has left upstream security support. A security-adjacent v1.0.0 needs a supported floor.
Fetch the corpus at a pinned commitCommit the corpus The corpus is FoxIO-licensed material. A fetch avoids redistribution; the pin keeps it reproducible.
A SyncProcessor wrapperLock every fingerprinter The lock-free core keeps the per-packet path fast for the sharded design. The wrapper serves callers who want safety instead of throughput.
Pure-Go capture reading via pcapgolibpcap via cgo Already done in e32e49e. A pure-Go build cross-compiles to five platforms.

Data model

The library holds no database. It holds in-memory state per connection and one embedded lookup table. FingerprintResult carries the fingerprint, the two raw forms, the method name, the addresses, the ports and the timestamp.

State that has no removal path

Every fingerprinter appends to a results slice and never truncates it. CleanupConnection does not touch it. That method exists, in its own documentation, "to prevent state leaks in long-running processes" — so a slice that grows for the life of the process defeats its purpose. Recorded as suspected finding S1 in the correctness audit.

Cross-cutting concerns

  • Concurrency. One Processor serves one goroutine. Callers route packets with GetShardKey, or share one SyncProcessor.
  • Error handling. A fingerprinter returns a non-fatal error, never a panic. A malformed packet never terminates the caller.
  • Input validation. Every packet is untrusted. Every parser bounds-checks every length field before it slices. Fuzz targets enforce this.
  • Logging. The library writes nothing to standard output or standard error. The command-line program owns all output.
  • Security. No network input or output, except the opt-in database update. govulncheck gates every pull request.
  • Performance. No additional per-packet allocation. SyncProcessor adds one mutex acquisition per packet.

Testing strategy

LayerCoversCommand
UnitOne function or fingerprinter, hand-built packet.go test ./...
RaceThe concurrency contract.go test -race ./...
ConformanceEvery method against every FoxIO vector.go test -tags conformance ./...
FuzzEvery parser entry point against generated input.go test -fuzz=Fuzz ./internal/parser
BenchmarkThe per-packet path, time and allocations.go test -bench=. -benchmem ./...

A change is done when the build succeeds on the module floor, -race passes, the linter reports nothing, conformance reports no new deviation, and coverage does not fall below the recorded floor.

Epic 2

Correctness audit

Read every file looking for a defect rather than a feature, then close what is found. The audit is read-only and produces a findings report; closure is a separate step with a regression test per finding.

28 requirements. Fourteen named checks: bounds checks on every length field, integer truncation, state removal paths, CleanupConnection completeness, empty-hash literals, sort stability, GREASE filtering against RFC 8701, swallowed errors. Three severities. Three suspected findings already recorded — the unbounded results slice, the sync.Once that blocks a database reload, and unguarded package-level lookup state.

Done when every file has an audit record, every confirmed finding names the commit that closed it, and every closure has a test that fails when reverted.

Depends on: Epic 0 · features/02-correctness-audit.md

Epic 3

Concurrency contract

Make the contract explicit, correct and tested. The core stays lock-free; a new SyncProcessor serves callers who share one instance.

24 requirements. A documented contract on Processor, all ten fingerprinters, doc.go and the README. SyncProcessor with four methods, one mutex, and no way to reach the inner Processor. Four race tests, including one that shares a bare Processor and is expected to fail under -race. A side-by-side benchmark.

Done when eight goroutines drive one SyncProcessor under -race and pass, and four sharded Processor values do the same.

Depends on: Epic 0 · features/03-concurrency.md

Epic 4

Conformance harness

Test every method against the FoxIO reference vectors, and produce the deviation list that Epic 5 closes.

37 requirements. A pinned-commit fetch script. Two adapters: the per-stream Python vectors (JA4/JA4_r/JA4_o/JA4_ro, JA4S, JA4H, JA4X, JA4SSH) and the per-packet Wireshark vectors, which are authoritative for JA4D and JA4D6 because the Python vector for dhcpv6.pcap is an empty list. Exact string matching — an extra fingerprint is as wrong as a missing one. A generated report. A CI gate that fails on any deviation and on a skip.

Done when make corpus fetches 38 captures and 74 vector files, and a one-character change to a fingerprint is caught.

Epic 5

Conformance gap closure

size unknown until Epic 4 runs

Close every deviation. The bar is byte-identical, with no exception: a deviation is closed, or a named requirement records why it cannot be and the maintainer accepts that record before release.

23 requirements. GRE, ERSPAN, VXLAN and Geneve decapsulation with a four-layer depth limit as a security control. Reading pcapng Decryption Secrets Blocks, plus a caller-supplied key log. Epic 6

Fuzz testing

Prove that no packet input can panic the library. Every packet is attacker-chosen input, and a panic in a monitor is a denial of service.

30 requirements. Twelve fuzz targets covering every parser entry point plus Processor.ProcessPacket. Each asserts no panic, no read past the input, a one-second bound for a 64 KB input, a 64 MB allocation bound, and determinism. Seed corpora tracked in git. A 30-second run on every pull request; a 10-minute nightly run that opens an issue with the crashing input attached.

Done when a deliberately removed bounds check is caught within 30 seconds.

Depends on: Epic 0 · features/06-fuzz-testing.md

Assumptions

  1. The maintainer accepts a Go 1.24 floor, and accepts that consumers on Go 1.22 and 1.23 stay on v0.3.0.
  2. FoxIO keeps publishing the corpus at FoxIO-LLC/ja4. A pinned commit protects the project from a move for the life of the pin.
  3. The FoxIO Wireshark vectors are authoritative for JA4D and JA4D6, because the Python vector for dhcpv6.pcap is an empty list.
  4. dev is the integration branch and master is the live branch. master stays releasable at all times.
  5. The maintainer files parity issues in Crank-Git/ja4plus personally. This project only records them.
  6. A conformance failure blocks a merge. A benchmark regression warns and does not block.

Risks and open questions

R1 — The license split (resolved 2026-08-06)

FoxIO License 1.1 covers JA4S, JA4H, JA4L, JA4LS, JA4X, JA4T, JA4TS, JA4TScan, JA4D, JA4D6, JA4SScan, JA4E and JA4SSH, and permits non-commercial use only. LICENSE-JA4 covers JA4 alone under BSD 3-Clause. This repository's README claims BSD 3-Clause for the whole library and links to a LICENSE file that does not exist. It also vendors FoxIO's ja4plus-mapping.csv.

Epic 1 implements the model the FoxIO FAQ recommends and names driftnet-io/go-ja4x as a good example of. This spec is not legal advice.

Resolved 2026-08-06. The maintainer accepts the dual BSD 3-Clause plus FoxIO NOTICE model as sufficient for v1.0.0. The project does not contact FoxIO before the release. The Epic 10 release gate is satisfied when docs/audit/license-decision.md records this.

Sources read 2026-08-06 at FoxIO commit 27f0cbf: LICENSE, LICENSE-JA4, License FAQ.

R2 — Two vectors may be unreachable (open)

chrome-cloudflare-quic-with-secrets.pcapng carries TLS secrets in pcapng Decryption Secrets Blocks, which gopacket does not read. dtls-udp.notest.cap carries a notest marker, meaning FoxIO excludes it from their own suite. Epic 5 treats both as named requirements with their own issues, not as silent exclusions.

R3 — Epic 5 cannot be sized until Epic 4 runs (open)

The corpus holds three encapsulated captures that tshark decapsulates and this library appears not to. The full deviation list does not exist until the harness runs, so Epic 5 is sized after Epic 4 finishes, not before.

R5 — gopacket upstream is unmaintained (open)

github.com/google/gopacket has published no release since v1.1.19 in 2022. The community fork is github.com/gopacket/gopacket. A dependency change after an API freeze is harder than one before it, so Epic 7 settles it first.

R4 — The Python port carries the same license gap (recorded, out of scope)

Crank-Git/ja4plus ships a plain BSD 3-Clause LICENSE with no FoxIO notice. The same correction applies there. This project records the finding and does not act on it.

Open questions inside feature sets

  • Epic 8, Q1 — Does the Python Collector belong in a Go library, or does a Go caller build it from Processor and GetShardKey?
