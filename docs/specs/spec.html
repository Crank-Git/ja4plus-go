What round 3 changed

Rounds 1 and 2 were written on 2026-08-06. The Python port, Crank-Git/ja4plus, shipped v1.0.0 on 2026-08-10 and v1.1.0 on 2026-08-11. Between those dates it recorded about thirty rulings, and about twenty of them end with a sentence of the form "The port must X, or the two implementations disagree on Y". In that sentence, "the port" names this repository.

Round 3 reads the port first and plans this repository second.

ChangeWhy
Added the divergence register — about 20 rows that name a change here. The port already ruled, and each ruling carries a measurement in a closed issue. Re-deciding them would produce two answers.
Removed the non-goal "the project does not add an eleventh method", for JA4LS only. The maintainer's rule of 2026-08-11: only a capability Go cannot achieve stays a non-goal. JA4LS is a defined method with published reference values.
Removed the non-goals on live capture and on being a monitor. pcapgo.NewEthernetHandle is pure Go on Linux; the libpcap build tag reaches macOS.

Deleted FR-parity-8 through FR-parity-14 — the cross-language test rig. The port's parity rule 3 rejects it: a rig couples two repositories that move at different speeds and fails for unrelated reasons. The shared vector set is the gate.
Added Epics 11–16: reference material, JA4LS, live capture, the documentation site, the mutation sweep, pre-release validation. Four are artifacts the port built and proved useful. Two are the maintainer's asks: GitHub Pages docs and tagged releases.
Added risks R6, R7 and R8. A large v1.0.0; cgo entering a no-cgo project; a ruling that can move on the port's side after approval.

Executive summary

ja4plus-go is a Go library and command-line program for JA4+ network fingerprinting. FoxIO publishes the JA4+ standard; this is an independent implementation. The library is at v0.3.0.

FoxIO names twelve methods. This project implements eleven of them once Epic 12 lands. JA4LFingerprinter writes both JA4L and JA4LS, so ten fingerprinters carry eleven methods. Read the ten as a count of fingerprinters, never as a count of methods.

The four things that must be true before the freeze

  1. The implementation produces the fingerprint the FoxIO reference produces.
  2. The concurrency contract is explicit and correct.
  3. The license states the terms FoxIO applies to the JA4+ methods.
  4. This project and the port produce the same fingerprint for the same packet.

None of the four is true today.

Three defects this repository holds today, confirmed against the code

  • ja4ssh.go:176-180 caps the JA4SSH window threshold at min(packetCount, 10). The port names this a defect of this repository and fixed the same shape on its own side in its issue #28.
  • ja4l.go:198 sets Type: "ja4l" and writes no JA4LS value.
  • ja4t.go:68, :73 and :87 write %d with no padding and no 00 sentinel, where two FoxIO implementations write a two-digit form.

ja4h.go:171-173 is already at parity, and Epic 8 adds a test that keeps it there.

Goals and non-goals

Goals

  1. Every method matches the FoxIO reference on every corpus capture, except where the register records a decline.
  2. This project and the port produce the same fingerprint, and expose the same interface where FoxIO specifies none.
  3. Eleven methods are implemented. JA4LS is the eleventh.
  4. The concurrency contract is documented on every exported type, and a race test proves it.
  5. The license files state the FoxIO terms.
  6. CI gates conformance, race detection, fuzz, vulnerability scanning, lint and coverage.
  7. The documentation site publishes to GitHub Pages on a push to the live branch.
  8. v1.0.0 releases with a frozen API and binaries for five platforms.
  9. Every ruling carries a register entry or a test, and every reading cites its source.

Non-goals — and the rule that decides them

A capability Go can achieve is in scope. Only a capability Go cannot achieve, or that FoxIO defines too little for any implementation to achieve, stays out. The maintainer set this rule on 2026-08-11.

Out of scopeBecause
JA4TScanFoxIO publishes no format and no implementation. A read on 2026-08-11 found technical_details/ holds material for ten methods and no file for it. One-to-one cannot be met for a method FoxIO does not define. Reversible when FoxIO publishes a format.
JA4ScanNo ruling exists. Three FoxIO records spell it two ways or omit it. This project decided nothing, so it states no reason — a stated reason would assert a ruling no round holds.
JA4ESame cause. LICENSE:3 is the one FoxIO record that names it.
Running the portNo test builds, imports or executes Python. Parity rule 3.
Changing the portA gap found here produces an issue there, and no code here.
Wire-speed performanceThroughput is measured and recorded. No target for v1.0.0.

Parity with the port

The port is at v1.1.0. Its own spec holds the register that governs this section. Three rules govern parity, adopted from the port without a change, so one rule set governs both repositories.

  1. FoxIO decides behaviour. Where FoxIO specifies output, the vectors decide. This outranks the port.
  2. The port decides interface where this project shipped nothing. Where this project shipped a name first, the rule runs the other way and the port adopted it.
  3. The gate is the shared vector set. No test in this repository builds, runs or imports the port.

Data model

The library holds no database. It holds in-memory state per connection, one embedded lookup table, and one tracked register.

The register — testdata/deviations.json

One entry per accepted difference from a FoxIO value. Fields: key, capability, ours, theirs, ruling, reason. A value decline records a disagreement an implementation change could close. A capability decline records a boundary no change closes.

A comparison the register names that now matches fails the suite. A closed deviation cannot sit in the file unnoticed.

State that round 3 adds

JA4TSFingerprinter gains a state table keyed by the five-tuple, because part e and the RST value both need the first SYN-ACK of the connection. Every fingerprinter still appends to results and never truncates it, which the correctness audit treats as a suspected defect — and the monitor makes that defect reachable, so Epic 13 depends on the audit closing it.

Cross-cutting concerns

ConcernThe rule
ConcurrencyOne Processor serves one goroutine. Route with GetShardKey, or share one SyncProcessor. The monitor owns one processor on one goroutine and takes no lock.
Error handlingA fingerprinter returns a non-fatal error, never a panic. A malformed packet never terminates the caller.
Input validationEvery packet is untrusted. Bounds-check every length field before slicing.
LoggingThe library writes nothing to standard output or standard error. The statistics line is command-line output.
Rulings and evidenceA ruling carries a register entry or a test. A reading cites a file and a line. Text copied from FoxIO material is verbatim.
SecurityNo network I/O except the opt-in lookup. The monitor opens an interface, reads packets and sends none. It reads a pcapng Decryption Secrets Block, because that block is part of the capture the operator already holds.

Assumptions

  1. The maintainer accepts a Go 1.24 module floor; consumers on 1.22 and 1.23 stay on v0.3.0.
  2. FoxIO keeps publishing the corpus. A pin protects the project for the life of the pin.
  3. The FoxIO Wireshark vectors are authoritative for JA4D and JA4D6.
  4. dev is the integration branch; master is the live branch and stays releasable.
  5. A conformance failure blocks a merge. A benchmark regression warns.
  6. The port's rulings are adopted without re-litigation. Each carries a measurement in a closed issue. This project re-measures only when a Go fact contradicts one.
  7. The macOS monitor is an opt-in build, and no released binary carries cgo. A macOS user who wants it builds from source with the tag.
  8. The documentation site needs Python in one CI job. Accepted, because no Go generator produces the same pages.

Risks and open questions

R1 — The license split is a release blocker (resolved 2026-08-06)

The dual model — BSD 3-Clause code plus a FoxIO NOTICE — is sufficient for v1.0.0. Epic 1 records the decision in docs/audit/license-decision.md. Round 3 adds one requirement: three FoxIO records at the pinned commit name nine, twelve and thirteen methods, so the README asserts no equality with FoxIO's list.

This spec is not legal advice.

R2 — Two vectors may be unreachable (open)

chrome-cloudflare-quic-with-secrets.pcapng carries TLS secrets in pcapng Decryption Secrets Blocks, which gopacket does not read. dtls-udp.notest.cap carries the notest marker, so FoxIO excludes it from their own suite. Both are named requirements with their own issues, not exclusions.

R3 — Encapsulation support is unscoped until Epic 4 runs (open)

Three corpus captures use GRE, ERSPAN, VXLAN and Geneve. tshark decapsulates all three; the library appears not to. Epic 5 is sized after Epic 4 finishes.

R4 — The port carried the same license gap (closed, out of scope)

The port shipped the correction in its own Epic 1. This project acts only on its own side.

R5 — gopacket upstream is unmaintained (open)

No release since v1.1.19 in 2022. The community fork is gopacket/gopacket. Round 3 raises the cost of this question: Epic 13 builds on pcapgo.NewEthernetHandle, so a migration now moves the monitor as well as the parser. Deciding after Epic 13 is more expensive than deciding before it.

R6 — This is a large v1.0.0 (resolved 2026-08-11)

Seventeen feature sets reach one tag. The gain is a freeze covering the final shape: no exported name moves in a v1.1.0, because JA4LS and the monitor are already in. The cost is a long path to the first v1 tag.

The maintainer decided on 2026-08-11 that the license correction waits for the full v1.0.0. Epic 1 could have shipped alone as v0.4.0, and it does not. Until v1.0.0 lands, the repository keeps claiming BSD 3-Clause for the FoxIO-licensed methods and keeps linking to a LICENSE file that does not exist. That is the accepted cost of the single-tag plan.

R7 — The macOS monitor introduces cgo to a no-cgo project (open)

CLAUDE.md states "No cgo. The build cross-compiles to five platforms." The libpcap build tag contradicts that sentence for one build. Epic 13 contains it three ways and then rewrites the sentence to state the containment rather than an absolute.

The residual risk: a macOS user builds from source without the tag and finds watch missing. FR-capture-24 answers with a message naming the tag.

R8 — A ruling can move on the port's side after approval (open)

Every register row is reversible, and the port shipped v1.1.0 on 2026-08-11. The mitigation is a check, not a promise: Epic 8 commits the port's register at a pinned commit and tests its row count. The test performs no network call, so it obeys rule 3. A count that moves reports that a re-read is due.

R9 — Three questions the port never settled (question 1 is closed)

This heading read Three rulings the port never made until 2026-08-12. Question 1 needed a reading and not a ruling, so the heading now names three questions. The maintainer confirmed on 2026-08-11 that all three needed a ruling. The maintainer closed question 1 on 2026-08-12, and technical_details/JA4.md:93 states the answer. Question 2 and question 3 stay open in this table. Question 2 is ruled, and this table does not record it: the maintainer ruled it on 2026-08-11, and #279 owns the repair of that row.

FoxIO settles neither of the two open questions, and the port settled neither. Each one is the maintainer's to rule on. An engineer who reaches one of them stops and asks. A guess produces two answers across the two repositories, which is the one outcome parity exists to prevent. A ruling lands in both repositories together.

QuestionAlready settledNot settledBlocks
What does the ALPN field write when the first ALPN value is empty? Closed on 2026-08-12. The answer is 00. Every part of the question. A one-byte first value repeats the byte and writes hh. A first byte outside 0x20-0x7E writes 99. An empty first value writes 00. Nothing. technical_details/JA4.md:93 states the rule, so the question needed a reading and not a ruling. Nothing. #50 built all three requirements.
