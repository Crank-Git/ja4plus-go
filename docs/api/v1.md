# The exported API of `v1`

**This page records every exported name of every published package of this module.** It
is the record that `v1.0.0` freezes. FR-release-1 through FR-release-5 of
`docs/specs/features/10-release.md` state the requirements, and #101 built the page on
2026-08-15 UTC.

## The promise of `v1`

**`v1` removes no name of this page, and it changes the signature of no name of this
page.** A release that must break one of them is `v2`, and `v2` carries a new import
path. That rule is the Go module compatibility promise, and this project adopts it
without a change.

**A name that this page does not hold is not frozen.** An unexported name moves freely,
and so does every name under `internal/`. `## What is published, and what is not` below
states the boundary.

**A later `v1.x` release adds a name, and the promise holds.** An addition breaks no
consumer, so the record gains a row.

## How the guard measures the count

**Never count a name by hand.** `api_test.go` measures the surface from the source, and it
fails when the measurement and this page differ. Run the guard with one command:

```
go test -run 'Api|Exported|ImportablePackage' -v .
```

`collectPackageAPI` in `api_test.go` is the measuring function. It reads each published
package directory with `go/build`, which applies the build constraints of the toolchain
that runs it. It then parses each file of `GoFiles` with `go/parser`, and it walks the
declarations for an exported name.

**A reader who wants the numbers reads the failure message.**
`TestTheApiRecordStatesTheMeasuredCounts` compares each count of the two tables below
against the measurement, and it prints the corrected row when the two differ. So a stale
count cannot reach the tree, and no reader has to trust a number this page states.

**The record uses the standard library, and it adds no module dependency.**
`## The measurement reads the standard library` below states the reading, because
`docs/specs/features/10-release.md` `## Interfaces` names `go/packages` and
`golang.org/x/exp/apidiff` instead.

**`internal/` is out of scope, and this page states that rather than leave it unstated.**
The `go` command refuses an import of a path that holds an `internal` element from outside
the subtree that the parent of that element roots. So no consumer of this module reaches
`internal/parser`, and an exported name there is not part of the exported API. The freeze
does not bind it.

**The rule belongs to the `go` command, and the Go language specification does not state
it.** The `## Internal packages` section of the Go 1.4 release notes states it:

> When the `go` command sees an import of a package with `internal` in its path, it
> verifies that the package doing the import is within the tree rooted at the parent of the
> `internal` directory. For example, a package `.../a/b/c/internal/d/e/f` can be imported
> only by code in the directory tree rooted at `.../a/b/c`. It cannot be imported by code
> in `.../a/b/g` or in any other repository.

Verified against: <https://go.dev/doc/go1.4#internalpackages>, retrieved 2026-08-15.

**`package main` is out of scope for the same class of reason.** A consumer imports no
`main` package, so `cmd/ja4plus` and the three programs of `examples/` publish no name.
The command-line interface of `cmd/ja4plus` is a separate contract, and
`docs/specs/features/10-release.md` holds it.

**`TestEveryImportablePackageIsRecordedOrDeclined` in `api_test.go` holds this table.** It
walks every package of the module, and it fails when a package is neither published,
`internal`, nor `main`. So a new published package cannot reach the tree without a row
here.

## The record holds a field and an interface method

**FR-release-3 names a type, a function, a method, a constant and a variable, and it names
no struct field.** This page records a field, and it records a method of an exported
interface. That is wider than FR-release-3, and it contradicts nothing in it.

The reason is the promise above. **A removed exported field breaks a consumer's build
exactly as a removed method does.** A consumer that reads `result.Fingerprint` stops
compiling when the field goes, and a freeze that does not name the field promises nothing
about it. The same holds for a method of `Fingerprinter`: a consumer that implements the
interface stops compiling when the interface gains a method.

**The `Kind` column separates the two classes.** A reader who wants the FR-release-3 set
alone reads the rows of kind `type`, `func`, `method`, `const` and `var`.

## The measurement reads the standard library

**`docs/specs/features/10-release.md` `## Interfaces` names two packages for this
comparison, and this page uses neither.** It states:

> The API comparison in FR-release-4 uses `go/packages` or `golang.org/x/exp/apidiff`. The
> engineer confirms the chosen package against its documentation before use, and records
> the choice in the issue.

**#101 chose `go/build` and `go/parser` of the standard library, and it records the choice
here.** Three facts decide it.

1. **Each named package adds a module requirement, and this module is at its API freeze.**
   `golang.org/x/tools` carries `go/packages`, and `golang.org/x/exp` carries `apidiff`.
   Neither one is in `go.mod` today, and a `require` line reaches the module graph of
   every consumer of `v1.0.0`.
2. **`apidiff` compares two versions, and FR-release-4 compares one version with a
   document.** `apidiff` answers a different question, and it needs a second package to
   load against.
3. **`go/packages` runs the `go` command to load a package.** `go/build` reads the
   directory in process, and it applies the same build constraints for this question.

**The sentence the requirement states is met: the choice is recorded, and it is recorded
here rather than only in the issue.** A reader of the record needs it more than a reader
of the issue does.

**The reversal path is issue #101.** A later change that needs a type-checked comparison —
a resolved alias, or a promoted method of an embedded type — adopts `go/packages` and
takes the dependency.

**Two limits of the measurement are measured, and this page states them rather than claim
the opposite.**

- **It reads the declared signature, and never the resolved type.** `ProcessorOption`
  records as `func(*Processor)`, which is the text the source declares.
- **It records an explicitly declared method, and never a promoted one.** No exported type
  of either package embeds another type today, so the two sets are equal at this
  measurement. `TestNoExportedTypeEmbedsAnotherType` in `api_test.go` fails when that
  stops holding.

2. **`pkg.go.dev` already serves the reader-facing signatures**, and the module proxy

without both halves.

## The one route for key material

**`WithKeyLog` on `NewProcessor` and on `NewSyncProcessor` is the only route by which key
material reaches a fingerprinter.** The maintainer ruled that shape on 2026-08-15 UTC, and
comment 5300957840 of #441 holds the ruling. #661 built the route.

**No `Fingerprinter` accepts a key log.** The `Fingerprinter` interface holds
`ProcessPacket`, `Reset` and `CleanupConnection`, and no one of them takes a `*KeyLog`. A
caller that holds a bare fingerprinter therefore decrypts nothing, and a caller that wants
decryption builds a `Processor`.

**Five names carry the route, and the freeze binds all five.**
`TestTheApiRecordNamesTheKeyMaterialRoute` in `api_test.go` holds this table, and it holds
the signature of each row.

| Name | Kind | Signature | What it does |
|---|---|---|---|
| `KeyLog` | type | `struct` | Holds the TLS secrets of one or more connections. |
| `ProcessorOption` | type | `func(*Processor)` | Sets one option of a `Processor` at construction. |
| `WithKeyLog` | func | `func(keyLog *KeyLog) ProcessorOption` | Returns the option that gives a `Processor` the key log. |
| `NewProcessor` | func | `func(options ...ProcessorOption) *Processor` | Takes each option and returns a `Processor`. |
| `NewSyncProcessor` | func | `func(options ...ProcessorOption) *SyncProcessor` | Takes each option and returns a `SyncProcessor`. |

**The variadic `NewProcessor` is source compatible with the form that `v0.3.0` shipped.**
`git show v0.3.0:processor.go` states `func NewProcessor() *Processor` at line 26, measured
on 2026-08-15 UTC. A caller that writes `NewProcessor()` compiles against both forms, so
the route added a capability and it removed no name.

**`NewSyncProcessor` is a new name, and `v0.3.0` shipped none of it.**
`git grep "func NewSyncProcessor" v0.3.0` reports no hit, measured on 2026-08-15 UTC. So
the name reaches the `Added` list of the `v1.0.0` section rather than the compatibility
reading above. #104 writes that section.

**A caller supplies one `KeyLog` to every shard.** The doc comment of `KeyLog` states that
the value does not change after construction. So a sharded caller gives one `KeyLog` to
each `Processor`, and the packet path reads it without a lock.

**The reversal path is #100 and #661.** A reversal that gives a `Fingerprinter` a key log
directly changes the exported surface, so it lands before the freeze or it lands in `v2`.
